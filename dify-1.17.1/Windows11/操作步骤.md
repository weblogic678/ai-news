# Dify 工作流安装配置 1.17.1：操作步骤

本包是联网安装辅助包，无容器镜像、无模型权重、无 API Key。制作环境未提供 Docker daemon、Windows 主机或客户服务地址，尚无真实部署截图；不得把静态检查当成实机兼容性保证。

## Windows 11 首次准备

1. 此包要求 Windows 11 x64。任务管理器→性能→CPU 检查「虚拟化：已启用」；关闭时按主板官方说明在 UEFI/BIOS 开启。
2. 从 https://www.docker.com/products/docker-desktop/ 安装官方 Docker Desktop，使用 WSL2 后端；其商业许可需按你的用途确认。若 WSL 缺失，管理员 PowerShell 执行 `wsl --install` 并按提示重启。Docker 首次启动、条款确认和重启无法由本包无人值守绕过。
3. 从 https://www.python.org/downloads/windows/ 安装 Python 3.10+，选择 Python Launcher；重新打开 PowerShell，确认 `py -3 --version`、`docker info`、`docker compose version` 成功。Compose 至少 2.24。
4. 将 ZIP 完整解压到自己的目录（不要直接在压缩包内运行）。启动 Docker Desktop 并等待 Engine running，双击 `start.cmd`，或 PowerShell 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1`。Bypass 仅影响此进程，不修改全局策略。
5. 等拉取结束，看到 Web page reachable 后访问下方地址；若窗口报错，保留报错文本（不要包含 Key）。中国网络镜像拉取可能较慢，包内没有未经核实的第三方镜像代理。

## 资源与网络

建议 Dify 4 核/8GB RAM/30GB 可用磁盘起步（官方最低 2 核/4GiB）；n8n/Flowise/AnythingLLM 根据数据量预留内存，本包示例不含本地大模型。AnythingLLM 默认向量后端还需 AVX2。首次联网从上游仓库/镜像源拉取，DeepSeek 调用需访问官方 API；所需流量随镜像变化，不承诺固定下载体积。

网页入口：`http://localhost:8080`。默认仅绑定 127.0.0.1。远程服务器可在自己的电脑使用 `ssh -L 8080:127.0.0.1:8080 用户@服务器` 再访问本机地址；不要直接改成公网监听。

## 日常命令

Windows：`py -3 installer.py status`；Linux：`python3 installer.py status`。将 status 换成 logs/stop/start/backup 可查看日志、停止、保留数据启动、冷备份。install 先拉取固定版本镜像，start 只用已有镜像。脚本无 down -v、删除数据或破解功能。

重复执行使用相同目录内的 runtime；发现非本包或不同版本 runtime 时拒绝覆盖。一个项目不能复制到两个目录同时启动（project name/端口固定）。升级先做冷备份，再按上游迁移说明单独处理；本包不做自动升级。

backup 会先停止服务，备份完成后仍保持停止，执行 start 恢复。Dify 冷备份包含 runtime 目录中的文件（含 volumes），需解压到同版本 kit 的 runtime 目录；其 PostgreSQL 数据恢复要求相同镜像版本。其他项目备份复制专用 volume 数据和 .env；恢复应在同版本的新建空 volume 中按产品官方文档导入，尚未做恢复实机验证。备份含敏感凭据，不上传 GitHub、不当作商品材料。

## 可选镜像离线运输

在已成功安装的联网 x86_64 主机执行 `python3 installer.py export-images`（Windows 用 py -3），会生成 Docker save .tar 与 .sha256；它们未随本商品包提供。将包与镜像 .tar/.sha256 一同带到同架构电脑，执行 `python3 installer.py load-images --archive images-xxx.tar`，再 start。Docker/Python 仍需预先安装；Dify 插件、DeepSeek API 和可选 embedding 下载仍可能需要联网。镜像条款须逐项核验后才能重新分发，不能据此宣称全离线 AI。

## 故障排查

docker info 失败：检查 Docker 启动与权限；Compose 版本低：升级官方插件；端口占用：先停止已有服务或在副本中一致修改端口/地址，勿自动杀进程；镜像拉取失败：检查官方 Registry 网络，不关闭证书校验；10 分钟等待超时：用 logs/status 看依赖是否健康，数据不删除；模型失败：按 DeepSeek 错误说明排查。

# DeepSeek 配置与费用

核验日期：2026-10-11。官方入口 https://platform.deepseek.com/ ，API 文档 https://api-docs.deepseek.com/ 。模型列表会变化，安装当天以账户可用模型为准。

1. 自行在官方平台注册、登录，按实际需要充值。API 调用费由买家自己的账户承担；本包不包含充值、账号、共享 Key 或模型授权。
2. 打开「API keys」，点击创建 API Key，起一个便于识别的名称。复制后保存在密码管理器中；不要发给卖家、写进 GitHub、截图、订单备注或示例工作流。
3. OpenAI 兼容基础地址填 `https://api.deepseek.com`；明确要求 `/v1` 的兼容界面可用 `https://api.deepseek.com/v1`。不要填聊天网页地址，也不要在 Base URL 中填 `/chat/completions`。
4. 当前官方聊天模型示例：`deepseek-flash`，另有 `deepseek-v4-pro`。不要沿用旧教程中的模型名；如列表中没有该模型，先刷新插件或用兼容供应商添加「自定义模型」。
5. 先用一小段不含敏感信息的文字试调用。成功后再上传自己的资料。资料会发往模型服务商，并非纯本地推理；不要发送他人的隐私、密码或未获授权的文档。
6. 401：Key 错误或已撤销；402/余额错误：检查账户余额；404/模型不存在：检查地址和模型；429：降低频率、等官方限流恢复；超时：检查 DNS、代理、防火墙及服务状态。不要通过关闭 TLS 校验解决。
7. 丢失 Key 时撤销并重新创建；更换 Key 后在产品凭据中更新。产品备份也可能含凭据，需私密保存。

## 可选官方 API 小额测试

包内 `test-deepseek.py` 使用隐藏输入读取 Key，不落盘、不打印 Key；输入 `yes` 后会产生一次真实 API 请求与可能的费用。Windows 执行 `py -3 test-deepseek.py`，Linux 执行 `python3 test-deepseek.py`。测试成功只代表 API 可用，仍需在产品界面测试模型配置。

## Dify 操作步骤

1. 访问 `http://localhost:8080/install` 创建自己的管理员账户，再登录。不要复用演示密码。本包不会自动创建管理员，也不会保存登录 Cookie。
2. 先创建无费用工作流：工作室 → 导入 DSL → 选择 `workflows/01-smoke.yml`。出现版本确认时核对目标为 Dify 1.17.1 / DSL 0.7.0。导入后应看到「输入文本 → 生成摘要请求 → 输出请求」。
3. 点测试运行，text 输入「今天完成安装，明天配置模型」。result 应为「请将以下内容整理为三条中文要点：」加输入原文。这个验收流程只生成请求文本，不会调用 AI、不产生摘要费用。
4. 配置模型：右上角头像 → 设置 → 模型供应商。查找 DeepSeek；尚未安装时去插件/Marketplace，核对发布者为 langgenius 后安装官方 DeepSeek 模型插件。完成后返回供应商页点击设置/添加凭据。
5. 填自己的 API Key；API Base URL 填 `https://api.deepseek.com`（官方插件也接受 `/v1`）。保存并通过凭据校验，刷新模型列表。选择 `deepseek-flash`，没有时先升级官方插件；也可在 OpenAI-compatible 供应商手动添加同名聊天模型，Base URL 填 `https://api.deepseek.com/v1`。
6. 创建真正的 AI 摘要：复制验收工作流，保留开始与结束节点，删除模板节点的两条连线；在中间加入 LLM 节点，选择上述 DeepSeek 模型，system 输入「你负责将输入文本整理成三条中文要点，保留事实，不补充猜测。」；user 输入框通过变量选择器插入开始节点的 text（不要只手打一个看似变量的普通字符串）。
7. 连接「开始 → LLM → 结束」，结束节点 result 绑定 LLM 的 text 输出；点测试运行，用相同输入核对三条要点。当前模型参数若不支持 temperature 等选项，使用插件默认值，不强加旧模型参数。
8. 验收后点击发布，记录应用名与版本。需要外部 API 时在发布菜单获取此应用的 API Key；它与 DeepSeek Key 是两种不同凭据，都不要公开。

本交付已制作 DSL 文件，但本制作环境没有 Docker 引擎或客户 Dify 地址，尚未导入真实 Dify 实例；不要把文件生成或配置校验宣称成部署成功。卖家应按第 1～8 步实机验收后补拍自己的真实界面截图。

## 镜像锁定与来源核验补充

manifest.json 记录已核验镜像的内容 digest。已取得 digest 的镜像按 digest 拉取，避免可变标签悄然更新。Dify 默认启用上游支持的 Qdrant 向量后端，替代制作时 Registry 返回 429 的 Weaviate。默认 profile 所需镜像均已取得 digest 并锁定；这仍不等于成功拉取或启动。未启用的其他数据库选项未统一锁定，不要自行改变 profile 后沿用本验收记录。n8n 使用官方 n8nio Docker Hub 发布镜像，原 docker.n8n.io 在本环境返回 429；AnythingLLM 镜像标签为 1.17.0，GitHub 标签 v1.17.0 不能直接照搬到 Registry。

## 可选：首次环境准备入口

Linux：已确认系统支持且希望安装官方 Docker/Python 时，运行 `sudo bash setup-linux.sh --install-prerequisites`。它配置官方签名的 Docker apt 源、安装 Docker Engine/Compose 和 Python 后启动本包；不删除冲突的旧 Docker 包、不修改 Docker 用户组。此入口以 root 运行，后续请统一使用同一权限与目录；系统包安装尚未实机测试。现有 Docker 环境用 `bash install.sh` 即可。

Windows：若希望通过 winget 安装 Python/Docker Desktop，在管理员 PowerShell 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-windows.ps1 -InstallPrerequisites`。该显式选项会接受对应安装包及源协议，请先确认 Docker Desktop 授权适用。安装后重新打开终端，按提示重启、启动 Docker Desktop 并完成首次设置，再执行 start.cmd。脚本不会绕过条款、硬件虚拟化或系统重启；不能宣传全新 Windows 无人值守完成安装。Windows 安装入口尚未在实机执行。

## Dify 向量后端选择

本包使用 Dify 1.17.1 官方 Compose 内已有的 Qdrant profile，固定上游 langgenius/qdrant:v1.8.3 镜像 digest；VECTOR_STORE=qdrant、QDRANT_URL=http://qdrant:6333，QDRANT_API_KEY 每个新安装随机生成，API/worker 与 qdrant 使用同一值。此版本来自 Dify 固定发行包，不宣称它是 Qdrant 的最新独立版本。未添加额外数据库或修改知识库业务代码。

## 减少界面操作：导入脚本

先完成管理员初始化。Windows 终端执行 `py -3 import-demo.py`，Linux 执行 `bash create-demo.sh`；也可在 Windows 双击 create-demo.cmd。默认只创建无模型费用的验收流程；需要同时创建 AI 摘要草稿时加 `--include-ai`（先按教程配置供应商）。脚本在你的本机终端询问邮箱和隐藏密码，不保存密码或登录 Cookie，也不要求 DeepSeek Key。不要把密码、Cookie 或 Key 发给卖家。

可先执行 `python3 import-demo.py --dry-run` 查看操作计划；Windows 用 py -3。支持 `--url http://localhost:8080` 或其他本机回环端口，拒绝非本机地址与跳转。远程部署先建立 SSH 隧道；不要关闭 TLS 校验。此实现对应 Dify 1.17.1 源码的 Console 接口，不是稳定的公开 API，升级后可能需要人工导入；已保留原有界面导入步骤。

脚本会创建新草稿，记录应用 ID、文件摘要与状态，重复执行核对已创建应用，不覆盖现有应用；未执行、未发布、未配置模型凭据。遇到超时或待版本确认时保留 attempting 状态并拒绝自动重试，请在 Dify 工作室核查。runtime/demo-import-state.json 不含密码/Key，但仍应私密保存；若残留锁文件，先确认没有导入进程，再处理锁。此脚本已做本地接口模拟测试，未连接真实 Dify 实例。

## 本机验收报告

安装并启动后，在此目录执行 Windows：`py -3 verify-local.py`；Linux：`python3 verify-local.py`。脚本只读取 Docker daemon、当前项目容器状态，并请求本机首页，不登录、不执行流程、不请求模型。报告保存到 `runtime/local-verification.json`，该目录不会进入交付包。退出码 0 仅表示本机可达，不能证明工作流、备份恢复或上架资格已经通过。首次启动未就绪时可稍后手动重测。报告不写入页面内容、账号或密钥。

真实验收还需本人完成：导入 smoke 流程并执行，记录输入和输出；备份后在独立空环境恢复并核对数据；本人配置 DeepSeek 凭据并确认计费后测试摘要。截图前遮盖邮箱、API Key、凭据、客户文档和地址。只使用自己的测试文本，截图注明版本、系统和测试日期，不以内容概览图替代运行截图。
